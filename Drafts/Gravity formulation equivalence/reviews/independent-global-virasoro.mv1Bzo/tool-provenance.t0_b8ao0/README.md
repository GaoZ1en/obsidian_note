## What the records do and do not say

Both JSON envelopes explicitly record `schemaVersion: 1`, the tool name, a call ID, a session ID, `completeness: "server-returned"`, `upstreamTruncated: false`, the actual `Get[...]` argument, and the received text content.

Inside that received text, `Messages -> {}` and `FailedOrUnevaluated -> False` are fields of the Wolfram association generated by the verification scripts. They are **not** independent wrapper/transport diagnostic fields. The first call also returns the script-generated `NumericalChecksPassed -> True` field.

These JSON envelopes do not expose separate stdout/stderr streams, an independent kernel exit-code field, an `isError` field, or a distinct transport-warning inventory. Their absence must not be restated as an independently recorded empty diagnostic inventory. The readable companions summarize the returned result; the JSON copies retain the available wrapper metadata and actual received content.
